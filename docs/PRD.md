## 1. 背景与目标

### 1.1 背景
面向外网的 WordPress 技术类网站需要稳定、持续地产出原创内容，以提升 SEO 与 AI 搜索（Perplexity、ChatGPT Search 等）收录。人工持续写稿成本高、频率难保证。

### 1.2 目标
- 一键自动化：定时自动选题、生成、发布 WordPress。
- 内容多样：覆盖 6 大技术主题，避免内容单调。
- 内容真实：杜绝编造版本号、价格、跑分等虚假信息。
- 自动归类：自动创建/复用分类与标签，无需人工维护。
- 防重复：同一篇文章不重复发布。

### 1.3 非目标（本期不做）
- 不做发布前人工审核（依赖提示词约束）。
- 不做基于语义的查重（仅按 slug 比对）。
- 不做多站点集中管理（单站点单工作流）。

## 2. 用户与场景

| 角色 | 场景 | 期望 |
|------|------|------|
| 站点运营者 | 开启工作流后自动发文 | 少人工干预，稳定产出 |
| 维护开发者 | 调整主题/频率/站点 | 文档清晰、可快速修改 |

## 3. 功能需求

### FR-1 定时触发
- 每 6 小时自动执行一次。
- 触发节点：Schedule Trigger。

### FR-2 自动选题
- 从 6 大主题中随机选取一个：
  1. 开源程序教程
  2. 主机测评
  3. 服务器运维
  4. WordPress 优化
  5. 在线工具教程
  6. Python/PHP 入门
- 输出：`{ category, instruction }`。

### FR-3 AI 生成内容
- 使用 DeepSeek 生成原创文章。
- 输出结构化 JSON：`title / slug / excerpt / content / category / tags`。
- 提示词强制“内容真实性”约束，禁止编造具体参数。

### FR-4 内容解析
- 解析 AI 输出（兼容纯 JSON 与 markdown json 代码块）。
- slug 为空时根据标题兜底生成。

### FR-5 重复检测
- 拉取站点已发布文章的 slug 列表。
- 比对目标 slug，重复则跳过本次发布。

### FR-6 自动分类与标签
- 分类/标签不存在时自动创建，存在时复用。
- 标签不足 3 个时自动补齐默认标签（技术教程、实用技巧、网站运维）。
- 以术语 ID 数组形式写入文章。

### FR-7 发布
- 以 `publish` 状态发布到 WordPress REST API。

## 4. 非功能需求

| 项 | 要求 |
|----|------|
| 可靠性 | 空响应、空标签等边界场景不中断链路 |
| 幂等 | 重复文章不重复发布 |
| 可维护 | 主题、频率、站点地址、默认标签均可配置 |
| 安全性 | 凭据（DeepSeek、WordPress）通过 n8n 凭据管理，不入库明文 |

---

## 5. 业务流程

```
定时触发(每6h) → 随机选题 → DeepSeek生成 → 解析JSON
  → 查重 → 判断重复
      ├─ 重复 → 结束
      └─ 非重复 → 准备术语 → 创建/复用分类 → 展开标签
            → 创建/复用标签 → 重组标签ID → 组装发布参数 → 发布文章
```

---

## 6. 验收标准

1. 工作流激活后每 6 小时自动执行一次。
2. 每次生成的文章标题、正文、摘要完整，分类与标签正确。
3. 同一 slug 的文章不会重复发布。
4. 分类/标签不存在时能自动创建。
5. 站点无标签时仍能补齐默认标签并正常发布。
